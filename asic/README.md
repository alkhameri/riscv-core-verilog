# SKY130 CPU macro

This flow implements `rv32_core` as a standard-cell hard macro in SKY130A with
`sky130_fd_sc_hd`. It preserves the five pipeline stages, tournament predictor,
M/U privilege support, PMP, atomics, interrupts, and retirement trace ports.
The FPGA RAM, UART, timer, board wrapper, and pad ring are outside this macro.
An integrating system supplies memory and peripherals through the existing
instruction and data interfaces.

## Checked implementation

The published layout comes from `sky130_local_preserved`, with final GDS-based
signoff completed on 2026-11-01. Its interconnect layers are shown in the
[KLayout render](../docs/images/rv32-core-sky130.png).

| Check | Result |
| --- | --- |
| Clock contract | 60 ns, 16.67 MHz |
| Macro area | 1.575 mm² |
| Worst setup slack, all nine corners | +1.987573 ns |
| Worst hold slack, all nine corners | +0.043448 ns |
| Setup, hold, slew, capacitance violations | 0 at every corner |
| Detailed-route, Magic, and KLayout DRC | 0 violations |
| GDS-based Netgen LVS | 0 mismatches |
| Antenna violations and disconnected pins | 0 |
| Magic/KLayout geometry XOR | 0 differences |
| Nominal static supply drop / ground rise | 0.810 mV / 0.701 mV |
| Final-netlist kernel regression | Pass, exact RTL trace match |

The gate-level kernel test retired 333,826 instructions, handled three timer
interrupts, and matched all 333,831 retirement and trap events in the RTL trace.
The instruction-model regressions, dependent ALU stream, and both directed
firmware seeds also passed on that same final netlist.

The [result directory](results/sky130/) contains compressed GDS, LEF, netlists,
all nine Liberty timing abstracts, the resolved SDC, and raw reports.
Start with [signoff.json](results/sky130/signoff.json) and
[validation.json](results/sky130/validation.json); use
[SHA256SUMS](results/sky130/SHA256SUMS) to verify the exported files.
Magic extraction emitted 11 warnings in PDK decap and diode cells. The
[extraction feedback](results/sky130/reports/gds-extraction-feedback.txt.gz)
is retained; illegal-overlap and LVS checks both passed with zero errors.

## Tools and reproduction

The container is OpenLane 2.3.10, pinned by multi-platform image digest in
[`tool.sh`](tool.sh). The run uses open_pdks revision
`0fe599b2afb6708d281543108caf8310912f54af`. OpenLane downloads that PDK into
`$PDK_ROOT`, or `~/.volare` by default. Expect several gigabytes of downloads
and substantially more space for intermediate databases and reports.
`OPENLANE_PDK_VOLUME` can instead select an existing, writable Docker volume
containing that same Volare cache. Native VM storage avoids slow PDK metadata
lookups through a macOS shared mount. The checked run used the populated
`riscv-core-openlane-pdk` volume for GDS extraction.

On Apple Silicon, the checked setup uses a native ARM64 Linux VM:

```sh
brew install colima docker sv2v verilator riscv64-elf-gcc
colima start openlane --cpu 6 --memory 12 --disk 120 --vm-type vz \
  --mount-type virtiofs --activate=false --ssh-config=false
export DOCKER_CONTEXT=colima-openlane
```

On Linux, use a working Docker daemon, Python 3, sv2v 0.0.13, and Verilator.
Run these commands from the repository root:

```sh
make test test-soc
asic/run.sh --run-tag sky130_60ns
python3 asic/check_signoff.py asic/runs/sky130_60ns build/asic/signoff.json
python3 asic/verify_netlist.py asic/runs/sky130_60ns
asic/tool.sh python3 asic/render.py asic/runs/sky130_60ns \
  docs/images/rv32-core-sky130.png
```

Prepare the kernel using the root README, then run `make test-kernel` before
adding `--kernel` to the netlist check. To compare every retirement and trap:

```sh
build/core/Vrv32_core --elf build/kernel/kernel.elf --kernel \
  --trace build/kernel-rtl.trace
python3 asic/verify_netlist.py asic/runs/sky130_60ns --kernel \
  --reference-trace build/kernel-rtl.trace
python3 asic/export.py asic/runs/sky130_60ns asic/results/sky130
```

Export requires clean physical signoff and a passing final-netlist regression
with an identical kernel trace. It packages compressed GDS, LEF, both netlists,
the resolved SDC and its source template,
OpenSTA Liberty timing abstracts for all nine corners, timing and physical-check
reports, the gate-test log, and SHA-256 manifests.

`prepare.py` converts the modular SystemVerilog with sv2v and records SHA-256
hashes of every input. Yosys then reads that generated Verilog. This avoids
incorrect bus-width elaboration observed with the container's Synlig frontend.
Generated-code lint waivers stay in the generated file; source RTL still uses
the normal strict lint checks. Predictor counters use packed tables so their
synchronous reset also works with the container's older Verilator.

The gate test uses cell functions generated by Yosys from the same Liberty
library used for synthesis and timing. Verilator 5.052 produced incorrect
sequential results with the PDK's UDP models. Liberty-derived flip-flops use
ordinary nonblocking assignments. This is a zero-delay functional simulation;
extracted static timing analysis checks physical delays separately.
Tap and filler cells absent from Liberty receive empty simulation models only
after their LEF confirms they have no signal pins. Missing functional cells
remain errors.

The build has two phases. Classic OpenLane maps, places, builds the clock tree,
and performs initial routing repair at 40 ns. The second phase closes a 60 ns
interface contract. It uses conservative routing estimates (2 times wire
capacitance and 1.3 times wire resistance), electrical repair, and two shared
non-inverting delay cells on each used data input before its fanout tree.
These cells provide input hold margin without adding clock cycles. The estimates do not alter
the technology database or the signoff extraction decks.

The custom final antenna step preserves the incremental routes produced by
`repair_antennas`. OpenLane's default subsequent full global route recreated
antenna violations on this design. All final antenna checks still run against
the actual detailed routes. After extraction, the flow repairs electrical and
timing violations using the maximum-RC SPEF at all three PVT corners, then
rebuilds signal routing and repairs antennas against the detailed geometry.
An incremental placement pass spreads the resized combinational cells while
holding every register and clock-tree cell in place. This prevents dense local
pockets after resizing. Pin-access points are regenerated before global routing.
Every repair is followed by fresh extraction and all nine signoff corners.
If electrical checks still fail, three separate OpenROAD steps resize existing
drivers using extracted loads, buffer long nets using conservative placement
estimates, and finish input buffering with monotonic drive-strength increases.
The estimated pass revisits newly inserted buffers before routing. Its fanout
target is temporarily relaxed to avoid splitting nets solely because antenna
diodes increased the pin count; the original target is restored afterward.
Separating these steps keeps cached placement estimates out of extracted STA.
A targeted closure pass repairs drivers still failing extracted
electrical checks. It uses 3 times estimated signal-wire capacitance for new
buffer segments, then restores hold margin and repeats routing and extraction.
If rerouting consumes that margin, a final pass optimizes against 0.45 ns slew
and 0.10 pF capacitance limits. It restores the 0.75 ns and 0.20 pF signoff
constraints before saving the design.

The final localized repair selects drivers that still fail extracted slew or
capacitance checks. It inserts one buffer near each source and another halfway
to its sink centroid. Existing cells retain their exact masters, locations,
and orientations. Incremental routing must preserve at least 95 percent of
existing signal routes. Coarse global-routing overflow is allowed in this
local pass because existing detailed wires consume reserved tracks; the final
detailed route must still have zero DRC errors. Fresh extraction, all nine
timing corners, and every physical check run again after each repair.
The build stops with an error if four broad closure passes and up to three
localized passes do not pass signoff.
The 40 ns attempt did not pass extracted timing;
it is an optimization target, not a supported operating frequency.

KLayout supplies the published GDS. Magic and KLayout stream-outs are compared
geometrically, and Magic extracts the published GDS for the Netgen LVS check.
Extraction copies the GDS into temporary storage inside the container and runs
the standard OpenLane extraction script there. This avoids slow filesystem
lookups across a macOS VM mount. The SPICE, feedback, and intermediate extraction
files are copied back into the run directory.
The export check also requires the sum of estimated worst supply drop and
ground rise to stay below 5 percent of nominal voltage. This is OpenROAD's
static, vectorless power-grid estimate at nominal conditions. It does not
include package effects or transient switching droop.

## Timing contract

[`constraints.sdc`](constraints.sdc) uses the configured 60 ns clock, 0.25 ns uncertainty,
0.15 ns clock transition, and 10 fF output load. All nonclock inputs have a
12 ns maximum and 0.5 ns minimum input delay. All outputs have a 12 ns maximum
and 0.5 ns minimum output delay. Reset, interrupts, bus responses, and
`time_value` must meet this same synchronous interface contract. There are no
false paths or multicycle exceptions. Early/late timing derates are 0.95/1.05.

Signoff checks cover nominal, minimum, and maximum interconnect extraction at
TT 1.80 V / 25 C, SS 1.60 V / 100 C, and FF 1.95 V / -40 C. Setup, hold, slew,
and capacitance checkers are enabled for all nine combinations.

Fanout eight is a synthesis and resizing target. Clock-tree sinks and antenna
diodes can exceed that target in the final fanout report. Acceptance requires
clean extracted setup, hold, slew, and capacitance checks; the raw reports keep
the fanout warnings visible.

OpenSTA can list constant outputs as unconstrained endpoints even with output
delays applied. This core has 29 tied-low output bits: `dmem_request_address[1:0]`
and `trace_cause[30:4]`. They have no changing launch signal. The reports retain
these warnings; any additional unconstrained endpoint needs investigation.

This is a core macro implementation. A complete chip still needs its system
integration, pad ring, power delivery, clock/reset source, and fabrication
review. The layout image is rendered from GDS by KLayout's viewer. It is not
a photograph of manufactured silicon, and ASIC timing does not establish
timing closure for the DE10-Lite FPGA build.
